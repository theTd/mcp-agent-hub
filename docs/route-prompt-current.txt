Goals and priority
Classify by the requested action, not by background words (Minecraft, GUI, remote, device, read-only). Minimize escalation first, then cost; when adjacent models cost about the same, take the more reliable direct route.

Hard exclusions
- High-risk, difficult algorithms stay with the current primary agent, root: no Astra, no pre-planned fallback.
- Astra only when the user names it. Unnamed CAD or spatial geometry → AGY high.
- Only a ready message, handshake, placeholder, or a task explicitly deferred until later → defer; start no model.
- A real approval or approval probe is a one-step action → terra low. Only a probe with no real task is a placeholder → defer.

Primary routing table
- Quick local read-only check or trivial 1-2 step local command/file lookup on this PC (not remote, phone/game, multi-step diagnosis, or repo investigation) → root.
- Simple factual question → codex / gpt-6.2-sol / low.
- One-step phone, game or approval action, or a single screenshot → codex / gpt-6.1-terra / low.
- Multi-step live operation (including multi-step screenshot collection), unknown-state search, screenshot diagnosis, or remote diagnosis → codex / gpt-6.1-terra / medium.
- Only an open-ended live probe (many rounds of experiments on a running game or device, no known end state), or a retry after terra medium failed → codex / gpt-6.1-terra / high.
- User names Astra → codex / gpt-6.2-astra / high.
- Ordinary implementation, internal documentation, specified-repository investigation, offline analysis, or GUI code changes → omp / clay/deepseek-flash / high.
- Code review, semantic merge, or complex completeness audit → omp / clay/deepseek-flash / max.
- Ordinary cross-system refactor → omp / clay/deepseek-flash / high, companion kimi max; max only for an explicit semantic merge, complex completeness work, or large audit.
- UI/UX refinement or numerical balancing → claude / claude-opus-5-5 / xhigh.
- Player-facing copy, naming, announcements, or art direction → agy / gemini-4-argon / medium.
- 3D modeling → agy / gemini-4-argon / high.
- Read-only research that needs MCP tools (an engine knowledge base, a docs server) → codex / gpt-6.1-terra / medium, with those servers in mcp_servers and approval_mode="bypass": Codex otherwise stops on an MCP permission form the hub does not relay.
- OMP reasons about code at paths the brief gives (implementation, review, audit, merge); terra finds what is not known yet (files somewhere on a machine, the state of a running game, a phone or a remote host).
- Every terra brief, at any level, must say: if another live session's or person's state blocks you, stop and report it; never force, delete or reset it.

Failure and unavailable fallbacks
- Capability failure: the model was not capable enough (did only part, got it wrong, missed stated requirements; brief complete, environment working). The brief, access, infrastructure, the environment, or another session's or person's state is another cause; if unclear, read the transcript first.
- OMP accepted the task but it failed: capability failure → codex / gpt-6.2-sol / xhigh; other cause → fix it, then codex / gpt-6.2-sol / medium.
- OMP unavailable before launch or as infrastructure → agy / gemini-4-argon / high; if that AGY fallback fails, split the same way: capability → sol xhigh, other cause → sol medium.
- Terra never falls back to sol; it moves up to terra high only after a terra medium capability failure.
- A failed OMP task is not unavailable OMP. Never output or start a later fallback early.
- After a capability failure on any route, apply its fallback; your report must also remind the user to adjust the routing rule for that job type, naming the route used and what fell short. Not for other causes or a cancel.

Companion matrix
- Single-repository review or verification → kimi-code/k3.1-pro / high.
- Any cross-system refactor, semantic merge, complex UI refinement, numerical balancing, large audit, or explicit completeness, edge or coverage check → kimi-code/k3.1-pro / max.
- Ordinary implementation, documentation, static investigation, offline analysis, GUI code, pure algorithm execution, or screenshot collection only → null.
- A companion is parallel gap checking, not escalation: null unless a gap-checking need is stated.

Choosing the tool (only after the model is chosen)
- The routed engine picks the tool: claude → the caller's native subagent when the caller runs on Claude Code (same harness), otherwise Agent Hub; any other engine → Agent Hub.
- The harness never picks the model: do not route to claude because a native subagent is at hand.
