Goals and priority
Route by the requested action, not background words (Minecraft, GUI, remote, device, read-only). Minimize escalation first, then cost; at near-equal cost prefer the reliable route.

Hard exclusions
- High-risk, difficult algorithms stay with root: no Astra, no pre-planned fallback.
- Astra only when the user names it; unnamed CAD or spatial geometry → agy / gemini-4-carbon / medium.
- Ready message, handshake, placeholder, or deferred task → defer; start no model.
- A real approval or approval probe is one-step → terra low; a probe with no real task → defer.

Primary routing table
- Quick local read-only check or trivial 1-2 step command/file lookup (not remote, phone/game, multi-step diagnosis, repo investigation) → root.
- Simple factual question → codex / gpt-6.2-sol / low.
- One-step phone, game or approval action, or one screenshot → codex / gpt-6.1-terra / low.
- Multi-step live operation (incl. multi-step screenshots), unknown-state search, screenshot diagnosis, or remote diagnosis → codex / gpt-6.1-terra / medium.
- Only an open-ended live probe (many rounds on a running game or device, no known end state), or a retry after terra medium failed → codex / gpt-6.1-terra / high.
- User names Astra → codex / gpt-6.2-astra / high.
- Ordinary implementation, internal docs, offline data or video metric analysis, or GUI code → omp / clay/deepseek-flash / high.
- Any research or investigation task: research, study, survey, source or data comparison, offline research, research of a technical approach, knowledge base, architecture or technical-scheme survey, named-repository research, or MCP-tool research (engine KB, docs server; attach the MCP servers) → omp / clay/deepseek-flash / max; unknown worktree/state search and unknown live/remote state (game, phone, device, host) stay with terra.
- Code review, semantic merge, or complex completeness audit → omp / clay/deepseek-flash / max.
- Ordinary cross-system refactor → omp / clay/deepseek-flash / high, companion kimi max; upgrade to max only for the review and audit cases above.
- UI/UX refinement or numerical balancing → claude / claude-opus-5-5 / xhigh.
- Player-facing copy, naming, announcements, or art direction → agy / gemini-4-argon / medium.
- 3D modeling, including model and entity proportions, a plain request with no failure stated → agy / gemini-4-carbon / medium.
- Terra briefs must state: if another live session's or person's state blocks you, stop and report it; never force, delete or reset it.

Failure and unavailable fallbacks
- Capability failure: brief and environment fine, yet the model fell short (partial work, wrong result, ignored a given requirement). Brief (including an incomplete one), access, infra, environment, or another live state is another cause; if unclear, read the transcript.
- OMP accepted but failed: capability → sol xhigh; other cause → fix it, then sol medium.
- OMP unavailable before launch or as infra → agy / gemini-4-argon / high; if that AGY fallback fails, split the same way: capability → sol xhigh, other → sol medium.
- AGY unavailable before launch → codex / gpt-6.2-sol / xhigh.
- An AGY task failing on a complete brief and a working environment is a capability failure → codex / gpt-6.2-sol / xhigh, with the reminder below.
- Terra never falls back to sol; after a terra medium capability failure it moves to terra high only.
- A failed task is not unavailable OMP; never start a later fallback early.
- After a capability failure, apply the fallback and tell the user to adjust the rule for that job type, naming the route and what fell short; not for other causes or cancels.

Companion matrix
- Single-repo review or verification → kimi-code/k3.1-pro / high.
- Cross-system refactor, semantic merge, complex UI refinement, numerical balancing, large audit, or explicit completeness/edge/coverage check → kimi-code/k3.1-pro / max.
- Ordinary implementation, docs, static investigation, offline analysis, GUI code, pure algorithm execution, or screenshot-only → null.
- Companion is parallel gap checking, not escalation: null unless a gap-checking need is stated.

Choosing the tool (only after the model is chosen)
- Claude → the caller's native subagent on Claude Code (same harness), else Agent Hub; other engines → Agent Hub.
- The harness never picks the model: don't route to claude because a native subagent is at hand.
